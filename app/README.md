# 月案・時間割作成支援アプリ（開発用）

小学校教員が毎月作成する「月学習予定表」を半自動で作成するための、インストール不要のローカルWebアプリです。
詳細な要件は `/root/.claude/uploads/.../41078101-Claude_Code_________________.md`
（初回開発指示書）を参照してください。

このディレクトリはソースコードです。教員に配布する完成品は、リポジトリ直下の
`release/` フォルダ（このアプリをビルドした単一HTMLファイル + 起動用ランチャー）です。

## 技術構成

- Vite + React + TypeScript
- Excel/Excelマクロファイルの読み取り: [SheetJS (`xlsx`)](https://www.npmjs.com/package/xlsx)（ビルド時にバンドル、外部CDN不使用）
- 端末内保存: IndexedDB（`src/storage/`。保存処理は生成ロジックから分離してあり、将来サーバーAPIに差し替え可能）
- ビルド成果物は [`vite-plugin-singlefile`](https://www.npmjs.com/package/vite-plugin-singlefile) で
  JS/CSSを1つのHTMLに埋め込んでいます。これは **必須の設計判断** です:
  通常のViteビルド（`<script type="module" src="...">`が別ファイル）は、
  `file://` で直接開いたときにChromeのCORSポリシーでブロックされ、真っ白な画面になります。
  1ファイルにインライン化することで、この制約を回避しています。

## ディレクトリ構成（将来拡張を妨げない設計 - 指示書 23章）

```
src/
  types.ts            ドメインモデル（型のみ、ロジックなし）
  storage/            保存層（IndexedDB）。他の層はこのモジュール経由でのみ永続化する
  excel/
    workbookReader.ts Excel構造の読み取り（SheetJS薄いラッパー）
    detectors/        ファイル種別ごとの自動判定ロジック（見出し文字列ベース、セル位置を固定しない）
    detect.ts         ファイル種別の推測 + 判定処理のディスパッチ
  features/           画面（ステップ）ごとのUIコンポーネント
  state/              画面をまたぐ状態（AppStateContext）
  components/         共通UI部品（ステッパー等）
```

生成ロジック（フェーズB以降）・単元進度管理・制約評価・出力処理は、まだ実装されていません。
それぞれ独立したモジュールとして追加し、`features/` 配下の画面から呼び出す構成にしてください。

## 開発

```bash
npm install
npm run dev      # 開発サーバー（http://localhost:5173 等）
npm run build    # dist/index.html を1ファイルとして出力
npx tsc -b       # 型チェックのみ
```

`npm run build` の後、`dist/index.html` をブラウザで直接開けば動作確認できます
（`file://` で開いても動作するのが要件です）。

## 既知の制約・今後の課題

- `detectors/` の自動判定は、実際に確認した5つのサンプルファイルの見出し語（多くが
  全角スペース区切り）に基づいてチューニングしています。学校が変われば見出し文字列が
  変わり得るため、確度が「低」「未検出」の項目は必ず利用者が確認・修正する前提です。
- `年間指導計画` の教科シートは教科ごとに列位置が揺れます（例:
  学活は単元名がD列、他の多くはB列）。総合的な学習の時間のように、1シートに
  複数の単元系列が並ぶ構造は、今回の自動判定では低確度になります（意図的に、
  推測だけで確定しない設計）。
- Clipboard APIは `file://` 起源では利用できないことが多いため、フェーズDの
  値コピー機能は「選択可能な表 + TSVダウンロード」を主手段とし、Clipboard APIは
  使える場合の補助とする方針です（指示書16章の通り）。
