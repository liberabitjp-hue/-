# 月案・時間割作成支援アプリ（開発用）

小学校教員が毎月作成する「月学習予定表」を半自動で作成するための、インストール不要のローカルWebアプリです。
詳細な要件は初回開発指示書（後に「フェーズ1完了済み」前提の改訂版が発行され、フェーズ名が
`A/B/C/D` から `1/1.5/2/3/4` に変更されている。**このリポジトリの中でフェーズ名を書く場合は
新しい呼び方（フェーズ1〜4、フェーズ1.5）を使うこと**。旧フェーズA＝新フェーズ1、B＝2、C＝3、D＝4。
別紙として「フェーズ1プロトタイプ 優位性強化・脆弱性低減 実装指示書」があり、フェーズ2以降へ
進む前の安定化作業（`docs/assumptions.md`参照）はこちらに従う）を参照してください。

このディレクトリはソースコードです。教員に配布する完成品は、リポジトリ直下の
`release/` フォルダ（このアプリをビルドした単一HTMLファイル + 起動用ランチャー）です。

## 技術構成

- Vite + React + TypeScript
- Excel/Excelマクロファイルの読み取り: [SheetJS (`xlsx`)](https://www.npmjs.com/package/xlsx)（ビルド時にバンドル、外部CDN不使用）
- 端末内保存: IndexedDB（`src/storage/`。保存処理は生成ロジックから分離してあり、将来サーバーAPIに差し替え可能）
- ビルド成果物は [`vite-plugin-singlefile`](https://www.npmjs.com/package/vite-plugin-singlefile) で
  JS/CSSを1つのHTMLに埋め込んでいます。これは **必須の設計判断** です:
  通常のViteビルド（`<script type="module" src="...">`が別ファイル）は、
  `file://` で直接開いたときにChromeのCORSポリシーでブロックされ、真っ白な画面になります。
  1ファイルにインライン化することで、この制約を回避しています。

## ディレクトリ構成（将来拡張を妨げない設計 - 指示書 23章）

```
src/
  types.ts            ドメインモデル（型のみ、ロジックなし）
  storage/            保存層（IndexedDB）。他の層はこのモジュール経由でのみ永続化する
  excel/
    workbookReader.ts Excel構造の読み取り（SheetJS薄いラッパー）
    detectors/        ファイル種別ごとの自動判定ロジック（見出し文字列ベース、セル位置を固定しない）
    detect.ts         ファイル種別の推測 + 判定処理のディスパッチ
  features/           画面（ステップ）ごとのUIコンポーネント
  state/              画面をまたぐ状態（AppStateContext）
  components/         共通UI部品（ステッパー等）
```

生成ロジック（フェーズB以降）・単元進度管理・制約評価・出力処理は、まだ実装されていません。
それぞれ独立したモジュールとして追加し、`features/` 配下の画面から呼び出す構成にしてください。

## 開発

```bash
npm install
npm run dev      # 開発サーバー（http://localhost:5173 等）
npm run build    # dist/index.html を1ファイルとして出力
npx tsc -b       # 型チェックのみ
```

`npm run build` の後、`dist/index.html` をブラウザで直接開けば動作確認できます
（`file://` で開いても動作するのが要件です）。

## 現在の実装状況（フェーズA）

- ✅ 起動（ダブルクリック相当の `file://` 直接オープン、管理者権限・インストール不要）
- ✅ 担当学級設定（年度・学年・組・担任・分科教科、複数学級の登録・切替）
- ✅ ファイル取込み（5種類のExcel/Excelマクロファイル、ファイル種別の自動推測）
- ✅ 自動解析結果の確認・対応付け（見出し語ベースの自動判定 + サンプル値 + 確度 + 手動修正 + 確定保存）
- ✅ 学校別書式設定の端末内保存・再利用・構造変化の警告
- ✅ 授業時数･下校予定時刻ファイルの月別複数改訂シートは自動採用せず、
  マッピング画面のプルダウンで毎回明示的に選択する方式
- ✅ 年間指導計画で1シートに複数の単元系列が並ぶ教科（総合的な学習の時間等）を
  「【系列名】」見出しから自動検出。加えて、マッピング画面から手動で項目
  （シート・項目名・セル範囲）を追加・削除できる
- ✅ ファイル取込み画面に取込み日時を表示。授業時数･下校予定時刻／固定時間割は
  年間を通じて随時更新される資料として明示し、同じ枠への取り込み直しで
  いつでも最新版に差し替えられる。ドラッグ＆ドロップでも取込み可能
  （`dataTransfer.items`へのフォールバックと、失敗時の明示的エラー表示つき）
- ✅ 担当学級設定を保存すると自動でファイル取込みへ、5ファイルすべて取り込むと
  自動で確認画面へ進む（ステップ間の手動遷移を削減）
- ✅ マッピング画面は左に確認項目一覧、右にシートプレビュー（結合セルを
  colspan/rowspanで再現、スクロールに追従して常に見える）の2カラム構成。
  すべて高確度のシートは折りたたんで確認の手間を削減
- ✅ マッピング画面は、担当学年の列だけ・担任が受け持つ教科だけに絞って表示
  （他学年の時数列、分科教科の年間指導計画、固定時間割の分科担当一覧は非表示）
- ✅ ファイル取込み時の事前検査（別紙4.2対応）: 空ファイル・50MB超・
  実体がExcelでないファイルは解析前に拒否、解析エラーはパスワード保護／
  破損／未対応形式などに分類して日本語表示、シートが無い/多すぎるファイルは
  保存前に中止、サンプリング上限を超えたシートは切り詰めたことを警告表示
  （`src/excel/fileValidation.ts`）
- ✅ バックアップの安全性強化（別紙「優位性強化・脆弱性低減」4.1対応）:
  `schemaVersion`/`appVersion`を記録、壊れた/想定外形式のバックアップは
  一切書き込まず拒否、復元直前に現在データを自動バックアップ、復元直後は
  同一セッション内なら「直前の状態に戻す」で即時に戻せる（`src/storage/backup.ts`）
- ✅ 判定ロジックのバージョン管理（`DETECTOR_VERSION`）。確定済みマッピングが
  古いロジックで作られていた場合は、ファイルが同じでも自動的に再判定し、
  再確認を促す（アプリ更新が古いキャッシュに隠れないようにするため）
- ✅ バックアップの書き出し・復元（フェーズD想定だが低コストなため先行実装）
- 🚧 フェーズB（生成ロジック）以降は未実装。画面のステップとしては用意してあり、

## 既知の制約・今後の課題

- `detectors/` の自動判定は、実際に確認した5つのサンプルファイルの見出し語（多くが
  全角スペース区切り）に基づいてチューニングしています。学校が変われば見出し文字列が
  変わり得るため、確度が「低」「未検出」の項目は必ず利用者が確認・修正する前提です。
- `年間指導計画` の教科シートは教科ごとに列位置が揺れます（例:
  学活は単元名がD列、他の多くはB列）。1シートに複数の単元系列が並ぶ構造は
  「【系列名】」見出しがあれば自動検出しますが、見出しの書き方が異なる学校では
  検出できず、手動追加欄での登録が必要です。
- Clipboard APIは `file://` 起源では利用できないことが多いため、フェーズDの
  値コピー機能は「選択可能な表 + TSVダウンロード」を主手段とし、Clipboard APIは
  使える場合の補助とする方針です（指示書16章の通り）。
