# 実装時の前提・決定事項

指示書23章・22章の方針（「勝手に固定的な業務ルールを作らず、仮定を一覧にして質問する」）
に沿って、実装中に決めた前提と、利用者に確認して決定した事項をまとめます。

## 利用者に確認して決定した事項

1. **複数校での利用は当面想定しない**。学校別書式設定（自動判定のマッピング）は
   ファイル種別ごとに1つだけ保存する、現在の設計のままとする。複数校での利用が
   必要になった時点で、保存キーに学校ID（または学校名）を追加する設計変更を行う。
2. **授業時数･下校予定時刻ファイルで同じ月に複数の改訂版シートがある場合、
   自動採用はしない**。マッピング画面で、月ごとに「どのシートを使うか」を
   プルダウンから毎回明示的に選ぶ方式に変更した（候補が1つしかない月は
   自動的にそれを使う。2つ以上ある月だけ、選択肢を空欄から選ばせる）。
3. **固定時間割ファイル内の「分科計画」表**（５年２組以外の学級の分科担当・時数も
   含む一覧）は保持しておく。将来、複数学級を横断して分科担当者の空き状況を見る
   機能（指示書12.3）の参考データとして使う想定。現状の自動判定（
   `fixedTimetable.specialistPlan`）は変更していない。
4. **「総合的な学習の時間」のように1シートに複数の単元系列が並ぶ教科**には、
   専用の検出ロジックを追加した。シート内の「【系列名】」という角括弧見出しを
   系列の区切りとして自動検出し、系列ごとに単元名・計画時数の候補列を提示する
   （実データでは3系列を正しく検出）。角括弧見出しが無い教科では、従来通り
   1系列として扱う。この自動検出でも拾いきれない系列がある場合に備えて、
   マッピング画面に「手動で項目を追加」欄を用意し、シート・項目名・セル範囲を
   指定して任意の項目を追加できるようにした（削除も可能）。
5. **授業時数･下校予定時刻.xlsx と R8固定時間割.xlsx は、年間を通じて随時更新
   される資料として扱う**。この2つは、取込み画面の同じ枠に新しいファイルを
   取り込み直すだけで、いつでも最新版に差し替えられる（既存の取込み機能で
   対応済み。表の形が変わった場合は自動解析結果の確認画面で警告する）。
   取込み画面には、取り込んだ日時を表示し、この2ファイルには「随時更新される
   資料」である旨の説明を追加した。フォルダ監視のような自動取り込みは、
   ブラウザから毎回フォルダへのアクセス許可が必要になり操作が煩雑になるため
   採用せず、手動での取り込み直しのみとしている。

## 決めた前提（他は今のところ仮運用のまま）

- ファイル種別の割当は自動確定しない。取込み画面の5つの枠にどのファイルを
  入れるかは利用者が選ぶ。中身から推測した種別と食い違えば警告するのみ。
- 学級プロファイルの同一性は「年度＋学年＋組」で判定する。
- バックアップの書き出し・復元は、本来フェーズD相当だが実装コストが低いため
  フェーズAの時点で先行実装した（対象は利用者情報・学級設定・学校別書式設定・
  取込んだファイルの構造のみ。月案の作成途中データ・確定版はまだ存在しない）。
